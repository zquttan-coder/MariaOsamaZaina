---
name: Instructor UI browser harness
description: Constraints for reliable Chromium/CDP tests around the instructor workspace
---

Top-level browser tests for the question-bank UI should run serially, set page state only after navigating to the app origin, and wait for instructor authentication before asserting API-backed rows. Scope Fetch interception to the local `/api/` origin rather than all requests, and let initial API responses settle before reloading the page; unrelated font requests and in-flight requests can produce stale interception IDs. For controlled selects, set the value through `HTMLSelectElement.prototype` before dispatching a bubbling `change`, and wait for the corresponding intercepted API request before proceeding to another filter. Avoid running the CDP suite alongside Vite builds or workflow restarts; concurrent dev-server activity can close an inspected target. Mock missing optional resources with their real not-found response, not a truthy empty array. The web preview can render while the separate API workflow is stopped, producing API 502s; unauthenticated latest/in-progress session reads legitimately return 404s.

For native `beforeunload` prompt tests, Chromium requires trusted user activation: use CDP mouse and text-input events rather than DOM `.click()` or synthetic input. After an unguarded reload, wait for a changed `performance.timeOrigin` before relying on the new document's DOM.

**Why:** Chromium/CDP target navigation is sensitive to concurrent browser lifecycles, localStorage written on `about:blank` does not initialize app page selection, and auth settling clears query data. Catch-all interception can also race external fonts or canceled API requests and surface `Invalid InterceptionId`. A login redirect can still cancel intercepted administrator-list requests; only those known cancellation errors should be filtered after the redirect, while other interception errors remain failures. React's wrapped select setter can make direct DOM assignment fail to emit a state change, and the next test action can race the query generated by the previous filter. Chromium also suppresses `beforeunload` prompts without trusted user activation, and a reload command can return while the old document is still observable. A browser run alongside a build and workflow restart once failed with a closed inspected target, while the isolated serial suite passed. An empty array is not a valid substitute for a missing single-resource response. The API and web artifacts have independent workflows, and the session endpoints report missing state with 404s.

**How to apply:** Run the serial CDP suite without concurrent Vite builds or workflow restarts. Intercept only same-origin API requests, navigate to the app before writing `pmp-sprint-page`, wait for mocked identity and initial API activity to settle, then navigate again to enter the requested page. Before signing in after concurrent query failures, wait for every related error state, zero pending requests, and a short quiet window; otherwise the redirect can cancel paused Fetch requests and trigger `Invalid InterceptionId`. If a deliberate login redirect still cancels administrator-list interceptions, filter only the exact expected cancellation after login and keep asserting all other interception errors. For a sequence of filter changes, wait until each expected request is observed before selecting the next filter. Keep API fixtures aligned with each endpoint's success and missing-resource contracts. When evaluating preview logs, distinguish backend 502s and expected no-session 404s from frontend render failures.
